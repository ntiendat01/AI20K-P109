# Kế hoạch triển khai nâng cấp trang tạo Purchase Request (PR)

## 1. Tóm tắt

Nâng cấp trang Tạo PR nhằm tối ưu hóa trải nghiệm người dùng, phân tách rõ ràng khối Metadata và khối chi tiết Sản phẩm. Bổ sung tính năng bulk upload qua drag-and-drop để thêm sản phẩm hàng loạt, đồng thời hỗ trợ lưu nháp (DRAFT) thay vì bắt buộc validate toàn bộ form. Output của form sẽ tuân theo Schema đa sản phẩm mới (multi-item). (US-ID: TBD)

## 3. Các bước

1. **Bước 1: Cập nhật Models & Schema Backend**
   - **Mục tiêu**: Thêm `metadata` và list `items` vào schema `PurchaseRequest`. Vẫn giữ lại các trường cũ (`category`, `requested_quantity`...) để LangGraph tiếp tục hoạt động tạm thời (không sửa các bước phía sau). Thêm enum cho status `DRAFT`.
   - **File sửa**: `src/models/purchase_request.py`
   - **Test**: Khởi động FastAPI không báo lỗi.
   - **Lệnh kiểm chứng**: `python -m pytest tests/api/test_prs.py`
   - **Commit**: `feat: update PurchaseRequest schema with items and draft status`
2. **Bước 2: Triển khai API Bulk Upload & PR Draft**
   - **Mục tiêu**:
     - API `/prs/extract-items`: Nhận file CSV/Excel. **Hardcode 1 template chuẩn** với các cột: `STT, Tên sản phẩm, Số lượng, Đơn vị, Ghi chú`.
     - Nếu file lỗi, **trả về lỗi cụ thể từng dòng** (VD: HTTP 422 `{"errors": [{"row": 2, "error": "Thiếu số lượng"}]}`).
     - Cập nhật logic create PR chấp nhận mode Draft.
   - **File sửa**: `src/services/procurement/purchase_requests.py`, `src/api/routes/procurement_workflow.py`.
   - **Test**: Test tạo PR draft và upload file lỗi/file đúng.
   - **Lệnh kiểm chứng**: `curl` gọi API `/prs/extract-items` thử file sample.
   - **Commit**: `feat: add robust bulk upload API with row-level errors`
3. **Bước 3: Xây dựng UI Khối Metadata & Action Buttons**
   - **Mục tiêu**: Thay form tạo cũ bằng cấu trúc chia Metadata. Thêm logic ComboBox ngân sách, tiền tệ, Date Picker (có shortcuts). Gắn nút Save Draft, Create PR.
   - **File sửa**: `frontend/features/purchase-request/purchase-request.js`, `frontend/styles.css`
   - **Test**: Manual test UI.
   - **Lệnh kiểm chứng**: Mở UI, nhập metadata, check JS console.
   - **Commit**: `feat(ui): implement PR metadata layout with quick select and draft buttons`
4. **Bước 4: Xây dựng Lưới nhập Sản phẩm & Drag-and-drop**
   - **Mục tiêu**: Tạo Dynamic Grid auto-append row mới khi Tab. Gắn Drag\&Drop zone gọi API `/prs/extract-items`. Xử lý hiển thị lỗi cụ thể từng dòng nếu API trả về lỗi.
   - **File sửa**: `frontend/features/purchase-request/purchase-request.js`
   - **Test**: Kéo thả file mock, kiểm tra xem grid render lỗi hoặc append data.
   - **Lệnh kiểm chứng**: Build và review tính năng tương tác lưới.
   - **Commit**: `feat(ui): add dynamic items grid and drag-and-drop bulk upload with error handling`
5. **Bước 5: Tích hợp Submit PR**
   - **Mục tiêu**: Gom payload từ Grid & Metadata gửi lên API POST `/prs`. (Map item đầu tiên hoặc tổng quantity vào các trường cũ để tương thích ngược). Cập nhật màn hình danh sách hiển thị label DRAFT.
   - **File sửa**: `frontend/features/purchase-request/purchase-request.js`
   - **Test**: E2E test quy trình Tạo nháp -> Xác nhận tạo.
   - **Lệnh kiểm chứng**: Flow end-to-end trên trình duyệt.
   - **Commit**: `feat: end-to-end integration for multi-item PR creation`

## 4. Thay đổi contract/schema

- Cập nhật model `PurchaseRequest`:
  - Thêm `metadata`: `{ budget, delivery_time }`
  - Thêm `items`: `[ { item_id, order_index, product_name, quantity, unit, notes } ]`
  - Giữ nguyên `requested_quantity`, `category` (cũ) làm fallback.
- Thêm `status`: `DRAFT` vào `PRStatus`.
- Thêm API Schema trả về lỗi upload: `{"errors": [{"row": int, "column": str, "message": str}]}`

## 5. Rủi ro và giả định

- **Giả định**: Backend sử dụng thư viện xử lý CSV/Excel cơ bản. Template được định nghĩa cứng bằng các cột chuẩn.
- **Rủi ro**: Việc lưu cả data kiểu cũ lẫn mới trong PR có thể gây dư thừa dữ liệu, nhưng đảm bảo an toàn cho phase này.

## 6. LƯU Ý / CẢNH BÁO CHO CÁC BƯỚC PHÍA SAU (WORKFLOW/LANGGRAPH)

⚠️ **TECHNICAL DEBT WARNING**:

- Hiện tại trang tạo PR đã chuyển sang Schema đa sản phẩm (`items`), nhưng Pipeline LangGraph (TCO, So sánh) **vẫn đang được giữ nguyên không sửa đổi** trong task này.
- **Để tương thích**, API tạo PR đang tạm thời gom dữ liệu để fill vào các trường cũ (`category`, `requested_quantity`, `estimated_budget`).
- **Hành động yêu cầu cho task tiếp theo**: Cần Refactor lại `calculate_tco` tool và hệ thống prompt của LLM để duyệt qua danh sách `items` thay vì dùng trường scalar số lượng duy nhất. Khi đó mới có thể bỏ hoàn toàn các trường cũ.
