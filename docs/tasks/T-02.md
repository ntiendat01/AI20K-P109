# T-02: Tạo PR & tải lên PDF
Trạng thái: Todo  <!-- Todo | In Progress | In Review | Done -->
Phụ thuộc: T-01

## Mục tiêu
Xây dựng các API endpoint bằng FastAPI để tạo Procurement Case (PR), tải lên tối đa 10 file PDF báo giá, và kiểm tra điều kiện (tối thiểu 2 file) trước khi cho phép bắt đầu quá trình phân tích.

## Acceptance criteria
- [ ] `src/models/pr.py` định nghĩa các Pydantic model cho request/response: tạo PR (yêu cầu số lượng > 0, deadline >= ngày hiện tại) và schema trả về.
- [ ] Lệnh `pytest tests/test_api/test_pr.py -k "test_create_pr"` pass, xác nhận validation của PR (chặn số lượng âm, deadline quá khứ).
- [ ] API `POST /api/prs/{case_id}/documents` nhận thành công `UploadFile`. Lệnh `pytest tests/test_api/test_pr.py -k "test_upload_documents"` pass (từ chối file không phải PDF, từ chối file > 2MB, từ chối file thứ 11).
- [ ] API `POST /api/prs/{case_id}/analyze` kiểm tra đủ số lượng báo giá. Lệnh `pytest tests/test_api/test_pr.py -k "test_analyze_trigger"` pass (trả về lỗi HTTP 400 nếu < 2 file PDF).
- [ ] `make check` pass (không có lỗi ruff/mypy mới).

## Tài liệu liên quan
- `docs/specs/user-stories.md` — Epic 1 (US-01.1, US-01.2, US-01.3): các quy định logic validate.
- `src/main.py` — file cần cập nhật để include router mới.

- `src/models/pr.py` — file cần tạo mới.
- `tests/test_api/test_pr.py` — file test cần tạo mới.

## Thay đổi contract
- **Thêm** endpoint `POST /api/prs` (tạo PR mới).
- **Thêm** endpoint `POST /api/prs/{case_id}/documents` (upload file).
- **Thêm** endpoint `POST /api/prs/{case_id}/analyze` (trigger chuyển state sang phân tích).
- **CẦN QUYẾT:** Cấu trúc JSON response cụ thể cho các API trên (vd: `{ "case_id": "...", "status": "success" }` hay cấu trúc chuẩn khác).
