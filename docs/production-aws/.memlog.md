- (constraint) Local development must remain runnable with docker compose up; production uses managed AWS persistence.
- (constraint) Do not use bmad-build or Jinja2 for this documentation task.
- (assumption) Initial production favors low cost over multi-AZ application high availability; the decision must be revisited before SLA commitment.
- (decision) PostgreSQL is the sole transactional system of record, preventing JSON and multiple SQLite stores from diverging.
- (decision) S3 owns uploaded PDFs and static frontend artifacts; application storage contains only object references and integrity metadata.
- (decision) SQS with a dead-letter queue owns durable asynchronous OCR and AI work; workers are idempotent and job state is stored in PostgreSQL.
- (decision) Terraform is the infrastructure source of truth; AWS CLI is reserved for inspection, migrations and break-glass operations.
- (question) Choose AWS Region, RTO/RPO, OCR hosting model, initial RDS availability mode and vector index destination before production provisioning.
- (decision) Supersedes the Terraform/SQS worker topology: local Docker Compose runs the full stack with PostgreSQL and local filesystem; production runs the application stack manually with Docker on EC2, using RDS PostgreSQL and S3 object storage.
- (constraint) Terraform is out of scope. Production deployment is a documented manual procedure; local docker compose up is the priority.
- (decision, supersedes prior AWS-managed storage plan) Production runs PostgreSQL, document files, workflow SQLite and Chroma on persistent EC2 Docker volumes. No RDS or S3 in this rollout; backup and restore from EBS/independent backups are operational requirements.
